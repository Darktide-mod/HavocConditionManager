# 3.6.10：地形连接放行与门状态校验

这次取消了额外巡逻、遭遇后补和回收补投对特殊地形连接的统一拒绝。门仍校验当前 AI 连接与开门状态，并在实际创建前复查。原版尸潮和事件出生选择保持原有逻辑。

## 寻路结果能否直接当作敌人可通行

当前借用的是原版 RoamerPacing 的出生选点通行规则。它来自敌人生成管理器，但不是粉碎者等每个兵种实际移动时的完整规则：原版 RoamerPacing 以空的导航代价覆盖表创建选点规则，而实际怪物导航使用各自兵种的导航配置。底层 AStar 也由 BOT 导航等系统共用。因此不能把“接口来自敌人生成管理器”当成“所有怪物都能执行这条路线”的证明。

源码依据：[出生选点规则](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/roamer_pacing.lua:82>)；[实际怪物的兵种导航规则](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/minion_navigation_extension.lua:20>)。

门的导航连接、开关状态和玩家控制面板是分别管理的。关卡可以通过 Flow 增加或移除门的导航连接；门还会通过导航阻挡区域控制通行。门连接已移除且没有其他通路时，不能靠该连接寻路；连接仍存在时，单凭路径成功不能判断门是否能完成开启。

原生 `can_open()` 根据门类型、开关状态和开启配置返回结果，并不检查玩家按钮是否激活。原生敌人的开门动作也直接调用不传玩家参数的 `can_open()`，允许时开门，再等待门口解除导航阻挡。因此，玩家按钮不可交互不等于怪物不能开门；反过来，只看 `can_open()` 也没有确认关卡是否已经禁用了这扇门的 AI 连接。

源码依据：[门状态与开启条件](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/door_extension.lua:375>)；[敌人的开门动作](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/bt_open_door_action.lua:65>)；[关卡启停导航连接](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/nav_graph.lua:280>)。

## 现在怎样处理

| 路径或门的情况 | 处理 |
| --- | --- |
| 包含攀爬、围栏、掩体翻越、跨跳、跳落等地形连接，完整原生路径成功 | 放行，不再按地形类型统一否决 |
| 门实体有效、AI 连接已启用，门口已解除导航阻挡 | 放行，即使 `can_open()` 因门已打开而返回 false |
| 门实体有效、AI 连接已启用，门口仍阻挡但原生 AI 开门条件允许开启 | 放行，由生成后的原生 AI 正常处理门 |
| 门口仍阻挡，且不允许原生开启 | 拒绝该候选 |
| 门的 AI 连接被禁用、实体消失或必需状态无法确认 | 拒绝该候选 |
| 寻路未完成、失败、终点不完整或连接类型无法识别 | 不生成，继续等待其他候选 |

校验沿用原生导航结果的四项记录结构：起点节点、终点节点、智能连接编号、导航层编号。只保存当前成功路线里的门编号，相同编号不重复保存。地形连接由原生寻路决定；门通过原版导航系统反查实体，并读取原版连接启用状态与门状态。

成功路线复用、异步结果完成和原版延迟队列真正创建单位时都会检查当前门状态。门在入队后变得不可用时取消本次创建，补投额度继续保留。校验不会开门、按按钮、解锁任务或修改原版导航规则。

完整敌人位置至玩家实际导航层的路径、出生距离与视野、编队落点连接、容量和原版生成暂停条件仍生效。保留原有一项共用异步查询、每秒最多一次新查询；本次门校验不启动第二次寻路，不增加全图扫描。

实现位置：[生成位置与门校验](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/projects/HavocConditionManager/src/HavocConditionManager/scripts/mods/HavocConditionManager/spawn_placement.lua:62>)。

## 旋转楼梯对面那批粉碎者

对应的旧日志是 `console-2026-09-10-18.36.53-12bde6d7-e9fd-4719-9914-a9d6ee893fd9.log`。第 12 批后补巡逻为 21 只粉碎者，UTC 18:44:02.917 开始在 `(38.285, -85.9433, 16.1507)` 创建；随后附近出现台沿连接失败，并在同一个门连接处出现六条粉碎者 `can't release smart object control(doors)` 记录。

原版这条日志对应退出导航动作接管失败，之后清除当前跟随路径。它不是“玩家专用门”或“没有路线”的明确错误码。日志缺少门开关状态、开启条件和逐只批次对应，不能据此确定该门只能玩家开启，也不能证明所有 21 只最后如何消失。

源码依据：[原版智能连接退出失败处理](<F:/SteamLibrary/steamapps/common/Warhammer 40,000 DARKTIDE/mod-work/havoc-redesign-20260905/build/hcm3610-fix/native-source/minion_navigation_extension.lua:840>)。
