# 3.6.9：补投不足的优化

上一局使用 3.6.7，日志为 console-2026-09-10-19.16.13-180e222a-f480-4a46-a1c0-4d7f97e41028.log。实际回收 104 只，其中一个已是补投单位；产生的 103 个有效额度只有 29 个补回，48 个留在等待中，26 个过期。29 / 103 约为 28.2%。3.6.8 改进了回收吞吐和未接战后方散怪，但尚未改变这套补投等待机制。

本版针对补投环节做了修改。目标是保住已接受的额度、在有条件生成时尽快平稳补入，并增加附近有效候选；不会把离线测试结果当作实机补投比例。

## 原因与对应处理

| 原有问题 | 3.6.9 的处理 |
| --- | --- |
| 额度 180 秒后过期，新额度合入旧批次时继承旧到期时间 | 已接受额度保留到本局结束；仍有固定的 32 条记录、256 个待补单位上限 |
| 只处理队首，某类原版调度暂停会挡住其他类别 | 从上次位置继续轮询可生成批次；一次只选择一个批次做选点或入队 |
| 批次之间固定停八秒，许多失败也要等八秒才重试 | 使用统一的至少 0.25 秒间隔，每秒最多四个请求；容量不足、调度暂停和无可用环境等使用短暂退避 |
| 原生附近点可能集中在别的楼层或同一条有问题的连接后面 | 原生附近点优先考虑玩家所在楼层，并额外采样玩家当前导航层周围的少量位置 |
| 大批次一次展开很多位置，后段可能超出已验证集结点范围 | 每次只展开最多八个补投位置，再逐个检查 |
| 原有回执难以区分补投受阻环节 | 增加容量、调度、场景、寻路等待、无点、展开位置及出队取消等原因计数 |

256 是等待额度的容量，不是在场敌人数上限。实际生成仍服从原版调度和在场容量。超过额度池容量的新额度会被拒收并计入丢弃；任务结束时未用完的额度会随本局状态清理。一个原单位最多产生一次额度，补投单位不能循环产生更多额度。

## 附近选点如何改进

仍共用一项异步寻路和一条可验证有效性的路线，每秒最多启动一次新查询。回收补投需要重新找点时优先试附近候选；已经通过验证且仍然有效的共用点位可以继续复用。

候选表最多包含两个原生前方点、两个原生附近点和四个局部导航点。局部采样围绕玩家实际所在导航层，交替使用 28 米、40 米半径；每次最多检查八个偏移位置，全局至少间隔四秒，最多留下四个候选。半径只是候选采样距离，实际距离仍按所有有效队员计算。

候选点投影到导航面并不等于允许生成。仍要求从敌人位置到玩家实际所在层存在完整通路；依赖门、翻越、跳落等特殊导航连接的路径继续保守拒绝。附近点必须对所有有效队员不可见、距每人至少 20 米、距最近队员不超过 60 米。每个展开后的出生位置还要连接到已验证集结点，原版队列真正创建单位时再次检查当前路线、距离和视野。

因此，不能承诺任何地图都能补完所有额度；没有有效路线时仍会等待。新增局部采样用于扩大合适候选的来源，不会先刷出敌人试路。

## 低开销约束

- 回收沿用 3.6.8：五秒采样、至少 0.25 秒间隔、每次更新最多一只，固定 64 个就绪引用。
- 补投每秒最多四个请求、每次更新最多一个；全局最多一个 HCM 补投请求等待原版中央队列处理。
- 轮询最多 32 条轻量额度记录，只为本次选中的一个批次做位置工作。在场容量不足时不启动补投选点。
- 选点共用一次异步查询，不阻塞游戏线程；局部导航采样另有四秒和八个位置的上限。
- 新增补投统计只在局末汇总，沿用有限的选点和回收日志；回收判定本身不增加寻路或全图扫描。

这是有界开销，不是零开销。没有用离线测试推断游戏帧率。

## 验证结果

24 组检查全部通过，50 个原版挂接方法解析通过，Vortex 安装验证通过。

新增测试执行原版敌人创建、注销、中央生成队列和队伍生命周期，验证：

1. 103 个实际回收产生的额度等待超过原先的 180 秒后仍全部保留。测试在第 300 秒恢复生成条件；103 个额度在 26 秒以内全部经原版创建补回，零过期丢弃。测试场景提供有效通路和足够容量，这不是原关卡实机回放。
2. 暂停的第一类额度不会挡住后面的两类，后两类完成后不会错误删除第一类额度；恢复后，三类各自按原兵种补回一次。
3. 非队首请求出队时路线失效会取消，保留正确额度和队伍归属；重试后五个额度恰好生成五个单位。整个过程最多一个请求等待处理。
4. 原版在场容量不足时保留额度、不做选点，容量恢复后继续补回。
5. 缺少原生遮挡点时，可以从玩家实际楼层周围取得新候选；仍拒绝特殊连接、当前可见位置和未完成的异步结果。
6. 保留先前的前方无路粉碎者、隔层目标、过近队友、动态路径失效、任务目标保护、未接战后方散怪和不重复补投等回归检查。
7. 300 次回收最多接受 256 个待补额度，另外 44 个明确计入容量丢弃，证明额度池保持有限。

完整检查中修正了测试环境中缺失的原版向量构造／坐标字段，并使“无隐藏点”场景同时反映当前视线；排队顺序测试按不同时间形成批次，避免依赖原版感知表的无序遍历。最终完整检查全部通过。
