# 设置界面开销优化

实际发现：DMF 每次 IO require 都执行窗口文件，窗口会再次读取 SoloPlay 设置、扩展词条目录并构建控件定义；选项模块又重复读取设置。读取当前词条还会反复写入同一值，DMF 将其标记为待保存。

现在按当前语言缓存窗口类和分页模块；选项模块复用窗口的目录。220 个通用控件引用一个只读模板，各控件内容和样式仍由原生 UIWidget 构造为独立实例。只在词条的规范化结果变化时写回。绘制时更新现有颜色表；分辨率未变时不分配视口表，同一悬停说明不再逐帧处理。

检查：40 次重复开窗只初始化一次类和目录；禁用／启用仍可重开；切换语言重建定义；控件颜色彼此独立；100 次未变词条查询零写入，非法旧值仍修复一次；120 帧仅计算一次视口和默认说明。完整独立运行、原版效果、环境与生命周期检查通过。

缓存仅用于界面定义，当前选择仍按开窗和操作读取；没有缓存游戏中的敌人生成结果。未测量实机帧率或开窗耗时，资源加载和实例创建仍有原生开销。
